## 2. The MasterShield Voice

This is how MasterShield speaks to homeowners — and why it works.

### 2.1 The Seven Layers of Brand Argument

| Layer | What It Means |
|-------|---------------|
| **Doctrine** | Engineering excellence is the only path to long-term reliability. |
| **Narrative Lens** | Always through the homeowner's eyes. Explain engineering through relatable stories, metaphors, and real problems they can see and feel. ("Why does my mulch wash out?") |
| **Argument Posture** | Problem → Mechanism → Proof → Performance → Benefit |
| **Claim Hierarchy** | 1. The homeowner's felt problem, 2. How it works (the relief), 3. Engineering proof, 4. Durability outcome, 5. What it means for the homeowner |
| **Evidence Profile** | Engineering specs, lab tests, installation mechanics, durability data |
| **Voice & Tone** | Conversational, confident, and relatable. Explain complex engineering like a knowledgeable neighbor, not a spec sheet. Aim for 7th-grade reading level. |
| **Reader's Role** | A homeowner who wants to make a smart, long-term decision — without needing an engineering degree. |

### 2.2 Choosing Your Article Type

The Router decides which archetype fits best based on three things:

1. **SERP Format** — If Google is showing lists, videos, or other non-narrative content, match that format (e.g., Comparison, Buyer Guide).
2. **Keyword Intent** — Map the keyword's intent and the cluster's Decision Axis to the right archetype.
3. **Rotation** — Don't use the same archetype twice in a row within the same cluster.

#### Rotation Protocol

MasterShield rotates through **12 approved archetypes**. The rule: never repeat the same archetype in consecutive articles within the same cluster.

**MasterShield's Preferred Archetypes:**

- Mechanism Deep Dive
- Diagnostic
- Failure Analysis
- Data Breakdown

#### All 12 Approved Archetypes

| # | Archetype | Reader Role | Structure |
|---|---|---|---|
| 1 | **Explainer** | Learner | Concept → Why It Matters → How It Works → Key Factors → Implications |
| 2 | **Diagnostic** | Investigator | Symptom → Possible Causes → How to Identify → Explanation → Solutions |
| 3 | **Myth-Buster** | Skeptic | Common Belief → Why Believed → Evidence Against → Correct Explanation → Better Approach |
| 4 | **Comparison** | Evaluator | Decision Problem → Criteria → Side-by-Side → Tradeoffs → Recommendation |
| 5 | **Buyer Guide** | Shopper | Buying Problem → What to Look For → Key Features → Common Mistakes → Best Choice |
| 6 | **Problem Escalation** | Concerned Homeowner | Small Problem → What Happens If Ignored → Escalation Chain → Real Risks → Prevention |
| 7 | **Mechanism Deep Dive** | Engineer | System Overview → Components → Interaction of Parts → Performance Factors → Design Implications |
| 8 | **Scenario Narrative** | Participant | Realistic Scenario → Problem Emerges → Investigation → Resolution → Lesson Learned |
| 9 | **Framework** | Strategist | Complex Decision → Key Criteria → Evaluation Framework → Example Application → Final Guidance |
| 10 | **Data Breakdown** | Analyst | Data Question → Data Source → Findings → Interpretation → Practical Meaning |
| 11 | **Failure Analysis** | Troubleshooter | Expected Outcome → Failure Scenario → Root Cause → System Weakness → Better Design |
| 12 | **Evolution Story** | Observer of Innovation | Original Problem → Early Solutions → Limitations → New Innovation → Modern Best Practice |

### 2.3 Words We Don't Use

Avoid these phrases:

- "best in the world"
- "guaranteed to work"
- "never clean your gutters again" — instead, use **"virtually eliminates"**

### 7.2 QA & Enforcement Checklist

The Pre-Publish QA Checklist (Doc 1710) must verify:

- [ ] **Archetype Rotation** — The selected archetype hasn't been used in the previous article within the same cluster.
- [ ] **Argument Structure** — The article contains the full `Problem → Mechanism → Proof → Performance → Benefit` argument chain (corrected July 30, 2026; was Mechanism-first).

- [ ] **Narrative Lens Adherence** — The article consistently frames the narrative through the homeowner's problem, using relatable stories and metaphors.
- [ ] **Evidence Profile Compliance** — The evidence used matches the profile in Section 2.1.

### 7.3 Module Dependencies

**Required Dependencies:** These modules must be referenced for any MasterShield page:

- **AEGIS 5X Mechanism Authority (Doc 142)**
- **Trust Layer System (Doc 141)**
- **Conversion Architecture Module (Doc 140)**

**Hierarchy Rule:** This Brand Module's voice and tone definitions (Section 2.1) supersede any general guidance in the **Brand Voice Guide (Doc 134)**.

### 7.4 Voice Adaptation by Funnel Stage

The core voice is a "knowledgeable neighbor," but it shifts based on where the reader is in their journey:

- **TOFU / MOFU (Pillar & Cluster Pages):** Keep it conversational, story-driven, and simple. 7th-grade reading level.
- **BOFU (Local Pages & CTA Sections):** Get more direct, clear, and action-oriented. Shift from *explaining* to *recommending*. Complexity can increase slightly — the reader is highly qualified now. But clarity and confidence remain paramount. The goal: remove friction from the final decision.
